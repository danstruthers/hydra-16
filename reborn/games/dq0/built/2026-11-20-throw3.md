## 1. dq0looks (tests/suites/dq0/senses.js, tests/dq0/looks.ref)

Traced first: three runs at 1f96d1cc gave the same 299 replies, all failing the old looks.ref at reply 221. The only
difference: six of game 8's denizens' senses' replies (dsense) came after a look instead of before it. Their requests
were the same (the same hashes), but each line carries the character's sight and chunks as they were at that moment,
so the moved lines differed too. The character's own 148 looks were identical to the old looks.ref's, in order.

The new form:

- **The character's looks**, compared exactly with looks.ref, in order: game, request, the record of what the
  character perceives, the squares seen and visible in every live chunk.
- **The denizens' senses' replies**, held to what each must say, not by count or place:
  - asked by a live denizen (named, its state set);
  - of the character, or of another live denizen;
  - answered with the SN_* kinds alone (seen, heard, smelt, look).
- **Every request posted answered**, each game: each dsense request counted as it's seen posted (its state REQ_POSTED,
  looked at each task switch) and its replies counted.
- **looks.ref** made again (DQ0LOOKS=write): 148 lines, the look lines alone, the same as the old file's look lines
  byte for byte.

Its notes: "looks 148; the denizens' senses asked and answered by game: 0:28/28 2:44/44 6:18/18 8:61/61". Those are
the old looks.ref's dsense counts too.

Stable over five runs on each of two layouts:

- this branch's build (the UI's overlay 13 changed, section 2);
- 1f96d1cc's game with the new test, the layout where the old test failed three runs in three.

All ten runs passed, the same notes each time.
