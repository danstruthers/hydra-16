# The referee's room for fighting between any two: overlay 10 (E10)

As built, for review.  Branch e10, 2026-11-19, from reborn-commands' e995c535.

## What was already done

room and room2 won the referee 62 bytes in overlay 4 and some main RAM, but at e995c535 the fight overlay (2) had
106 bytes free and the main RAM 2,246 (198 over its 2,048 floor).  None of the HarnMaster library was in an overlay:
harn.o, harncmbt.o, harntest.o, harnkey.o and harnfall.o were all in the main RAM.

## What was built

- **Overlay 10** (dq0harn.cfg, bank.s's OVMAX 10).  fight.c's guard, effect, dealt, aspect_of, prone and strike moved
  there from overlay 2: what guards a side, the effects told, what a strike deals and with what aspect, and the strike.
  Overlay 2's attack, mishap and o_fight call them through stubs (effect, strike, dealt, aspect_of); mishap's direct
  call of prone is now the effect it made, through effect's stub.
- **Overlay 10's own words.**  cc65 puts all of a file's string literals in the read-only data segment named at the
  file's end, which for fight.c is overlay 2's.  Overlay 10's strike copied "your " from overlay 2's address with its
  own bank in the window, and wrote past the line into its own code (the fetch guard caught it in dq0armour).  The four
  literals are now named arrays in overlay 10's read-only data.
- **HarnMaster's falls in overlay 10** (hfall.c).  The library's harnfall.c is built into overlay 10, as hbdice.c and
  hdig.c build the house's dice and digging into theirs; sheet.c's harm calls harn_fall through a stub.  Every pointer
  it is given is the main RAM's.
- **dq0hard's budget 1,700M cycles** (tests/suites/dq0/save.js).  At e995c535 it finished at 1,596M of 1,600M.

## Open

- The rest of the library stays in the main RAM.  harncmbt's harn_location_name and harn_severity_name return pointers
  to their words, and harn_protection is a table its callers read, so in an overlay their callers in other overlays
  would read the wrong bank.  harnkey's 552 bytes are read only by swapped part 1, whose image is 178 bytes under the
  swap area's size.
- No check finds a literal or a table that is read from another overlay's bank.  A scan of every game's .s files
  finds one other case: dq0's said.s, where overlay 27's code names _said_rows in overlay 28's read-only data.
