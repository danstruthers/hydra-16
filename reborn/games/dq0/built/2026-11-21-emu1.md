Neither shows a version or the free memory, so HyBASIC's doesn't either. In HyForth's form:


- **Its kind:** "QuickBASIC's kind" is README.md's wording for HyBASIC.

Room: BASIC's first bank went from 12,164 to 12,223 bytes (75% of 16K, +59). The ROM disk is unchanged at 1,468 of 1,472 blocks. No main RAM was used (the string is in the bank's code).

## 2. Dead keys in the browser emulator

**The fault:** with a layout like US-International, `'` `"` `` ` `` `~` `^` are dead keys. The terminal was a canvas taking `keydown` only:

- The dead key's keydown has the key `Dead`, which was dropped.
- The browser's composed text never reached the page, because a canvas has no text input.
- So `"` + `H` sent only `H`, `"` + space sent nothing, and `PRINT "Hi"` came out as `PRINT Hi`. That's why BASIC seemed broken.

**The fix:**

- **sim/web/keys.js (new):** keyText, latin9 and the Latin-9 tables moved here from page.js, plus a small `KeyInput`. No DOM is used, so node can test it.
- **page.js and page.html:** the terminal's focus is now a hidden textarea over the canvas, so the browser's text input works. The canvas still draws the terminal and takes the mouse. Every `term.cv.focus()` is now `term.focus()`. The focus outline and the cursor block follow the textarea.

What the keys do now:

- **Keys keydown knows:** special keys, Ctrl's control characters, Alt's ESC prefix and a letter typed on its own are sent from keydown as before. Nothing changes for a US layout.
- **A dead key:** keydown leaves it, and the key after it, to the browser. The browser's text is sent instead, from either path:
  - Firefox: an `input` event (`insertText`).
  - Chrome and Safari: `compositionend`. Their composition `input` events are ignored, so nothing is sent twice.
  - An IME's keys (`Process`, keyCode 229, `isComposing`) work the same way.
- **Results:** dead + space gives the accent itself (`'` `"` `` ` `` `~` `^`). Dead + letter gives the composed letter (`á` as $E1, `ñ`, `ê`, `ü`). Where the layout doesn't compose (`'` + `t`), it gives both.
- **If no text comes:** a key held back after a dead key whose text never arrived is sent at the next keydown, so it isn't lost.
- **Letters the Hydra lacks:** a spacing accent goes as its ASCII key (`´` as `'`, `¨` as `"`). A letter with an accent goes as the accent then the letter (`ẽ` as `~e`, `ő` as `"o`). Pasted text goes through the same mapping.
- **AltGr** (which Windows reports as Ctrl+Alt) now gives its character. Before, it sent ESC and the character.

**Tested in node:** `node sim/web.js --check` now also runs `checkKeys`. It replays keydown/input/composition event runs as each browser gives them:

- US typing `PRINT "Hi"` and Enter.
- US-Intl `PRINT "Hi"`, Firefox-style and Chrome-style.
- Each dead key + space.
- Composed letters.
- `'t`.
- Dead + Enter.
- A held key with no text.
- Arrows, also in application cursor mode.
- F1, Backspace, Tab, Delete and Esc.
- Ctrl-C, Alt-x and Ctrl-Alt-Left.
- AltGr é and €.
- IME text.
- latin9's fallbacks.

All pass, and the worker check still boots and answers.

**To try it in a browser:**

1. Build (`node build.js`, or `node sim/web.js --serve`), then open bin/hydra-16.html.
2. In Windows, switch the keyboard to ENG-INTL (Win+Space).
3. Click the terminal and type `basic`, then:
   - `PRINT "Hi"` (that's `"` then H, `"` then space). It should print `Hi`.
   - `PRINT "á ñ ê"` (`'` then a, `~` then n, `^` then e) should print those letters.
   - `PRINT "'t"` should keep both characters.
4. Try the arrows, Ctrl-C, Tab and Backspace at rc's prompt.
5. Do the same in Chrome and in Firefox, since they deliver dead keys differently.

I could test only the event sequences, not a real browser.
