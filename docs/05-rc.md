# 5. The shell: rc

**rc** is the Hydra's shell underneath everything: Plan 9's shell, by Tom Duff, small, written in 65C02 assembly and run
in place from the paged ROM (`reborn/modules/rc/`).  It's the shell of scripts and of C's `system()`, and HyForth's,
hylang's and HyBASIC's shells hand it every line that isn't theirs.  It's also a shell of its own: type `rc` for an rc
session.

This chapter is a tour, with examples run on the Hydra.  If you know a Unix shell, rc will look familiar, with fewer
rules: every variable is a list, quoting is one kind of quote, and there's no word splitting to surprise you.
[The differences](#rc-for-a-unix-user) are summed up at the end.  Plan 9's paper, *Rc: The Plan 9 Shell*, is the full
story of the language.

## The shells on the Hydra

| Shell | Prompt | What it is |
| :---- | :----- | :--------- |
| `forth -l` | `/>` | **The login shell**: HyForth, where a line that starts with a Forth word or a number is Forth, and any other line is rc's ([below](#at-hyforths-prompt)) |
| `rc` | `%` | rc on its own |
| `hylang -l` | `hylang>` | hylang as a shell, by the same rule |
| `basic -l` | `>` | HyBASIC as a shell, by the same rule |

Each window has a shell of its own.  Which shell a window gets is `/lib/shell`'s line (`/bin/forth -l`); a card's
`/lib/shell` comes first in `/lib`'s union, so `/bin/rc -l` in a card's `/lib/shell` gives every window rc.

## Starting rc

| Command | What runs |
| :------ | :-------- |
| `rc` | An rc session: a prompt (`% `), each line run, until `exit` or Ctrl-D |
| `rc -l` | The same as a login shell: its namespace made from `/rom/lib/namespace` (and a card's), then the profile |
| `rc -c 'line'` | The line run, and rc ends with its status |
| `rc file args` | The file's commands (`$0` the file, `$*` the args) |

At the prompt, the console edits the line ([the line editor](04-drivers/serial.md#reading-a-line-cooked-mode)):
Backspace, the arrows, Home and End, Ctrl-U, and Up and Down through the lines before.  Ctrl-C ends what's running, and
rc goes on.  A command that isn't finished (an open `{`) gets the second prompt, a tab.

## Commands

A command is a program and its arguments, run and waited for.  `/bin` is searched for a bare name (and `.`: `$path` is
`(. /bin)`); a name with a `/` in it is used as it is.  A command's **status** is `$status`: its exit message, or its
code; empty or `0` is success.  Most of `/bin`'s tools are **bank programs**: a command whose program is one runs in
rc's own task (the kernel's `RUN`), from a RAM bank of rc's where it stays loaded, so the next time it starts at once;
any other program, and each stage of a pipeline and each command run in the background, gets a task of its own
([the kernel](03-base/kernel.md#bank-programs)).

| Form | Meaning |
| :--- | :------ |
| `a; b` | a, then b (a new line is the same) |
| `a & b` | a in the background (`$apid` its task), then b |
| `a && b`, `a \|\| b` | b only if a succeeds, or only if it fails |
| `! a` | a, its status turned over |
| `{ a; b }` | a group: one command |
| `# words` | a comment, to the line's end |

```
% ls /nosuch || echo it failed
ls: /nosuch: not found
it failed
% ! ~ a b && echo not the same
not the same
```

## Words and quoting

Words are separated by spaces and tabs.  **`'...'` quotes**: nothing inside is special, and `''` is a quote inside it.
That's the only kind of quote.

**Globbing** makes names from `*` (anything), `?` (one character) and `[a-z]` (one of a set; `[~a-z]` one not in it),
sorted, by reading the directories; a pattern that matches nothing stays as it is.

**`^` joins words**: two single words make one; a word and a list make a list, the word joined to each; two lists of the
same length join item by item.  A caret is put in for you between a word and a `$` right against it (`pre$x`).

```
% x=(apple banana cherry)
% echo $x^.txt
apple.txt banana.txt cherry.txt
% echo pre^$x
preapple prebanana precherry
% echo 'single quotes: $x stays'
single quotes: $x stays
```

`#` starts a comment, so a device's name must be quoted: `ls '#c'`.

## Variables

**Every variable is a list of words**: `x=word`, `x=(a b c)`, `x=()` (empty: as good as unset).  There's no word
splitting: `$x` is its words, however many spaces they hold.

| Form | Value |
| :--- | :---- |
| `$x` | its words |
| `$#x` | how many |
| `$x(n)`, `$x(n-m)` | the nth word (from 1), or those from n to m |
| `$"x` | its words joined by spaces, one word |
| `` `{command} `` | the command's output, split into words at spaces, tabs and new lines |

```
% x=(apple banana cherry)
% echo $x(2) $#x
banana 3
% n=`{echo hello | wc -c}
% echo $n
6
```

**Variables are the environment's** ([the environment](04-drivers/kdev.md#the-environment)): a program rc starts gets a
copy (`/env/x` in its task, `getenv` in C, `$x` in hylang), a list's words each with a zero byte after it.  `x=1 cmd`
sets `x` for that command alone.

rc's own: `$status`, `$apid` (the last background task), `$task` (rc's task), `$path`, `$prompt` (the prompt, then the
second prompt), `$*` and `$0` (a script's arguments and name), `$window` (the shell's window), `$home`.

One more goes to a program's environment, though it isn't a variable of rc's: **`prog`**, the path rc starts the
program from (`/bin/ls`, `./round`, `/ram/round`: a `$path` directory and the name, or the name as typed), put there
just before it starts.  A program that starts copies of itself (the C samples) finds its own file by it (`getenv
("prog")` in C, `/env/prog` as a file).

## Redirection

| Form | Meaning |
| :--- | :------ |
| `< file` | fd 0 from the file |
| `> file`, `>> file` | fd 1 to the file, made or emptied; or added to its end |
| `>[2] file` | fd 2 to the file (any fd: `>[3]`, `<[4]`) |
| `>[2=1]` | fd 2 made a copy of fd 1 |
| `>[2=]` | fd 2 closed |

```
% ls /nosuch >[2=1] | wc -l
      1
```

Devices are files, so redirection reaches them: `echo note 0 60 >/dev/sndctl` plays a note, `cat /dev/time` reads the
clock.

---

## Pipelines and the background

`a | b` runs a and b at once, a's fd 1 into b's fd 0 (a pipe, 512 bytes held); `a |[2] b` takes a's fd 2.  Each stage is
a program; a stage that isn't one (a group, a function) runs as `rc -c` on its text.  The pipeline's status is its last
stage's.

```
% ls /rom/bin | sort -r | head -3
xmodem
xd
wc
```

`a &` runs a without waiting: `$apid` is its task, `wait` waits for the background tasks (`wait $apid` for one), and
`ps` shows them.

## Control flow

| Form | Meaning |
| :--- | :------ |
| `if(cmd) a` | a if cmd succeeds |
| `if not b` | right after an `if`: b if the `if` didn't run its command |
| `for(x in words) a` | a for each word, `$x` it (`for(x) a`: for each of `$*`) |
| `while(cmd) a` | a while cmd succeeds (`while()` for ever) |
| `switch(word){ case pattern ... }` | the commands after the first `case` whose pattern matches |
| `~ subject pattern ...` | success if the subject matches one of the patterns (glob patterns, matched as words, not names) |

```
% for(f in $x) echo fruit: $f
fruit: apple
fruit: banana
fruit: cherry
% if(~ $x(1) apple) echo first is apple
first is apple
% switch($x(3)){
	case b*
	echo starts with b
	case c*
	echo starts with c
	}
starts with c
```

## Functions

`fn name { commands }` makes one; its arguments are `$*` and `$1` ...; `fn name` alone removes it.  Functions are in the
environment too (`fn#name`), so a child rc has them.  `whatis name` says what a name is: a function's text, a variable's
value, or a program's path.

```
% fn greet { echo hello, $1 }
% greet world
hello, world
% whatis greet
fn greet { echo hello, $1 }
% whatis path prompt
path=(. /bin)
prompt=('% ' '	')
```

## Scripts

A file of rc commands runs with `rc file args`, or by its own name if its first line is `#!/bin/rc`: rc runs a file that
isn't a program with the interpreter its `#!` line names (Plan 9's way).  `/rom/bin/scom` is one:

```
#!/bin/rc
# scom [-l | n]: the old riff ... a song: once; its loop n more times; or -l, till it's stopped
if(~ $1 -l) play -l /rom/songs/scom.zsm
if not play /rom/songs/scom.zsm $*
```

`. file` runs a file's commands in this rc (its variables and functions stay); `exit [status]` ends a script, or rc.

Ctrl-C reaches a script's rc as well as what it's running: rc waits for that to end (a program may take the note
itself, finish up and say so), then ends with its status, rather than going on to the next command.

## Built-ins

These change rc's own task, so they can't be programs:

| Built-in | What it does |
| :------- | :----------- |
| `cd [dir]` | The current directory (none: `$home`, else `/`) |
| `bind [-a \| -b] [-c] new old` | new at old in rc's namespace: in place of what's there, or `-a` after it, `-b` before it in a union; `-c`: creates go there |
| `mount [-a \| -b] [-c] dev old [spec]` | A device's tree at old (`mount '#f' /mnt/c 1`: card 1's file system) |
| `unmount [new] old` | old's member new gone, or all of old |
| `newns` | The default namespace made again |
| `exit [status]` | rc ends |
| `exec [command]` | The command's program runs in rc's place (`EXEC`): rc is gone, and the program's status is what rc's parent waits for.  Only if it can't be run does rc go on |
| `wait [task]` | Wait for background tasks |
| `eval words`, `. file`, `builtin cmd`, `whatis name`, `shift [n]` | As Plan 9's |

## Namespaces from the shell

Each shell has its own namespace ([namespaces](03-base/files.md#namespaces)), and rc's built-ins change it.  Since
there are no search paths, putting programs where `/bin` sees them is a `bind`:

```
% ls /sd/0/sample | head -5
as/
c/
hi
nsum
tick
% hi Ann
rc: hi: not found
% bind -a /sd/0/sample /bin
% hi Ann
Hello, Ann!
I'm task 6, in /.
```

`bind -a` put the card's samples **after** what `/bin` had; `bind -b` would put them **before**, so they'd run in place of
the ROM's programs of the same names.  The change is this shell's alone: other windows don't see it, and the programs
this shell starts share it.

More uses:

* `bind -b /ram/test /bin`: try a new version of a program without touching anything else.
* `mount '#f' /mnt/c 1`: card 1's files at `/mnt/c`.
* `bind '#c2' /dev`: this shell's `/dev/cons` becomes window 2's console.
* `ns` shows the namespace as the `bind` and `mount` lines that would make it; `newns` starts again from the default.

```
% ns | tail -4
bind -c '#fr/2/lib' /lib
bind -a '#fs/lib' /lib
bind -a '#fx/lib' /lib
bind '#P' /pc
```

## Windows from the shell

The console's windows ([windows](04-drivers/serial.md#windows)) are files and commands:

* `new-window` makes a window with a shell, in this group; `new-window -g` in a group of its own (a new session);
  `new-window 'ls -l; sleep 5'` runs a command in it.  It isn't waited for: the window goes when its program ends.
* `echo layout rows >/dev/wctl` tiles the group's windows; `echo layout tabs >/dev/wctl` shows them one at a time.
* `echo compiling >/dev/label` titles the window; `echo status 3 of 9 >/dev/wctl` sets its footer's status.
* `cat /dev/text` is the window's screen and scrollback as text; `cat /dev/snarf` the cut buffer.
* `$window` is the shell's window.

## How a shell starts: the profile

A login shell builds its namespace from `/lib/namespace` (`newns`), then runs its profile: rc's is `/lib/profile`,
HyForth's `/lib/forth/profile.fs`, hylang's `/lib/hylang/profile.hl`.  Each is found through `/lib`'s union, so one on a
card or the RAM disk takes the place of the ROM's.  rc's:

```
# /rom/lib/profile: what each shell runs as it starts (rc -l: after newns), before its first prompt.  $window is
# its window (init's: the kernel starts init for each window): its console goes at /dev, and its notes (Ctrl-C) to
# the shell's note group.

prompt=('% ' '	')
if(~ $#window 0) window=0
if(! ~ $window 0){
	unmount '#c' /dev
	bind -a '#c'^$window /dev
}
echo -n group >/dev/consctl
```

So each window's shell has its own window's console at `/dev`, and takes its window's Ctrl-C.  HyForth's profile does the
same in Forth.  Your own settings go in a profile of your own on a card: copy the ROM's and add to it.

## At HyForth's prompt

The login shell is HyForth (`forth -l`), prompt `/>`.  A line whose first word isn't a Forth word or a number is an rc
line, run whole by an rc of its own (`rc -c`) and waited for, so pipes, redirection, globbing and quoting are rc's
there.  But:

* **a simple command runs in HyForth's own task**: a line that's a program and its arguments, with none of rc's
  special characters in it, runs in HyForth's task if its program is a bank program (`RUN`), no rc started, and stays
  loaded for the next time.  Any other line is rc's.
* **each line is a new rc**: a variable or function set on one line is gone on the next (`$status` is kept for the
  next line).  For an rc session, type `rc`.
* **the line's last command runs in rc's place**: `rc -c` runs the last command of its text with `EXEC` when it's a
  simple command whose first word is a program, so `ps` at the prompt takes one task, as if HyForth had started it,
  and its status is HyForth's to see.  A pipeline, a sequence's earlier commands, a built-in or a function run as
  rc's always do.
* **`%` before a line** makes it rc's whatever its first word (`% free` when a Forth word `free` is loaded).
* **`cd`, `bind`, `mount`, `unmount` and `newns` are Forth words** there, taking rc's arguments, so they change the shell's
  own directory and namespace, as rc's built-ins do.

[HyForth](06-languages/hyforth.md#hyforth-as-a-shell) has the rest.

## rc for a Unix user

| In sh or bash | In rc |
| :------------ | :---- |
| `x="a b"` | `x='a b'` (one word) or `x=(a b)` (two) |
| `"$x"` | `$x` (no splitting, ever) or `$"x` (the words joined) |
| `$(cmd)` | `` `{cmd} `` |
| `if [ ... ]; then ...; fi` | `if(test) cmd` or `if(~ $x pattern) cmd` |
| `else` | `if not` |
| `for x in a b; do ...; done` | `for(x in a b) cmd` |
| `case $x in a*) ...;; esac` | `switch($x){ case a* ... }` |
| `f() { ...; }` | `fn f { ... }` |
| `2>&1` | `>[2=1]` |
| `$?` | `$status` (a message or a number; empty or `0` is success) |
| `$#` | `$#*` |
| `$PATH` and search paths | `bind` into `/bin` |
| `export x` | (every variable is in the environment) |
| `source file` | `. file` |
